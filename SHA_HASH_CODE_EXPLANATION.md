# SHA-256 Hash Code & Evidence Report Generation

This document explains how SHA-256 hash codes are generated and how evidence text files are created in the Deepfake Detection Platform.

## 📋 Overview

The platform generates SHA-256 hash codes for uploaded videos to ensure file integrity and creates detailed evidence reports in text format for legal/organizational use.

## 🔐 SHA-256 Hash Generation

### Location: Frontend (React)

**File:** `deepfake-frontend/src/services/api.js`

### Function: `calculateFileHash()`

```javascript
export const calculateFileHash = async (file) => {
  try {
    // Step 1: Convert file to ArrayBuffer
    const buffer = await file.arrayBuffer();

    // Step 2: Generate SHA-256 hash using Web Crypto API
    const hashBuffer = await crypto.subtle.digest("SHA-256", buffer);

    // Step 3: Convert hash to hexadecimal string
    const hashArray = Array.from(new Uint8Array(hashBuffer));
    return hashArray.map((b) => b.toString(16).padStart(2, "0")).join("");
  } catch (error) {
    console.error("Hash calculation failed:", error);
    return "unavailable";
  }
};
```

### How It Works:

1. **File Reading**: The uploaded video file is converted to an `ArrayBuffer`
2. **Hash Generation**: Browser's built-in `crypto.subtle.digest()` API generates SHA-256 hash
3. **Format Conversion**: Binary hash is converted to hexadecimal string format
4. **Error Handling**: Returns 'unavailable' if hash calculation fails

### When It's Called:

- **File:** `deepfake-frontend/src/components/VideoUpload.jsx`
- **Function:** `handleAnalyze()`
- **Timing:** Before sending video to backend for analysis

```javascript

  // ... other code ...

  try {
    // SHA-256 hash is calculated here
```

### How Text File is Generated:

1. **Content Creation**: Report content is built as a multi-line string
2. **Blob Creation**: Content is converted to a `Blob` object with MIME type `text/plain`
3. **URL Generation**: Browser creates a temporary download URL using `URL.createObjectURL()`
4. **Download Trigger**: Hidden anchor element (`<a>`) is created and clicked programmatically
5. **Cleanup**: Temporary URL and DOM element are removed

### When It's Called:

- **User Action**: When user clicks "📥 Download Evidence Report (TXT)" button
- **Location**: Evidence Report tab in the guidance section
- **File Name Format**: `Deepfake_Evidence_Report_[timestamp].txt`

## 🔧 Technical Details

### SHA-256 Hash Properties:

- **Length**: Always 64 hexadecimal characters (256 bits)
- **Uniqueness**: Each file has a unique hash (collision probability ~0)
- **Integrity**: Any file modification changes the hash completely
- **Security**: Cryptographically secure, cannot be reversed

### Text File Properties:

- **Format**: Plain text (.txt)
- **Encoding**: UTF-8
- **Size**: Typically 2-3 KB
- **Structure**: Organized sections with clear headers
- **Legal Use**: Suitable for evidence documentation

### Browser APIs Used:

- **`crypto.subtle.digest()`**: SHA-256 hash generation
- **`file.arrayBuffer()`**: File reading
- **`Blob()`**: Text file creation
- **`URL.createObjectURL()`**: Download URL generation

## 🛡️ Security & Privacy

### Hash Security:

- Generated client-side (browser)
- No hash data sent to server
- Used only for evidence integrity
- Cannot reveal file contents

### File Privacy:

- Videos processed in memory only
- No permanent storage on server
- Hash provides integrity verification
- Evidence reports contain no video data
